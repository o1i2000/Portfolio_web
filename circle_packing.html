Circle Packing: Greedy vs Random Search vs Genetic Algorithm

The task is to fit a set of circles of different sizes into the smallest possible enclosing circle. I wrote three solutions in Processing (Java) and compared them. The code has been ported to JavaScript so it runs live in your browser. Choose a test set, adjust the parameters and press run.

How it works

The placement rule

Every method uses the same decoder, so the only thing that changes is the order of the circles. The first circle goes in the centre. For each next circle, 360 candidate points are tested around every circle already placed. Points that would cause an overlap are rejected, and the circle goes at the free point closest to the centre. The score is the radius of the smallest circle, centred on the middle, that encloses everything.

Greedy

The circles are sorted by radius and placed in that one order. It is deterministic and needs only a single placement, so it is very fast. It also gives a baseline that the search methods need to beat.

Random search

The order is shuffled N times, each one is evaluated, and the best is kept. This is a simple, unbiased search that shows how much a smarter method actually adds.

Genetic algorithm

Each individual is a permutation of circle IDs. Parents are chosen by tournament selection. With probability equal to the selection pressure the fittest of the tournament wins; otherwise a random entrant does. They are recombined with ordered crossover (OX), which keeps the child a valid permutation, and a swap mutation is then applied. The best ordering found in any generation is kept.

What the comparison shows

  • Order matters a great deal. For the same circles, a good ordering can shrink the boundary by 25–30% compared with a smallest-first greedy order.
  • Random search improves quickly at first and then levels off. The GA keeps improving because crossover passes on useful sub-sequences of placements.
  • For a fair test, use Match GA evaluation budget so random search gets as many placements as the GA. The chart's x-axis counts placements, not generations, for the same reason.
  • The algorithms are stochastic, so run them a few times. The spread between runs is part of the result.

Note: this browser version keeps the original logic. To make it faster, it compares squared distances and skips candidate points that could not beat the current best. These changes give the same placements.
